# 项目评审报告与优化建议

> 评审时间：2026-06-12　评审范围：全部代码、流程定义、日志与架构文档（原 `ARCHITECTURE.md`）

## 一、项目目标回顾

1. Agent（OpenClaw / Claude Code 等）通过紫鸟 Skill（`.cursor/skills/ziniao-assistant`）跑通店铺操作任务后，将过程**沉淀**为 0 tokens 可重复执行的任务。
2. 沉淀的任务**只需传参**（如时间、店铺名）即可执行，且具备**异常判断、多分支选择**能力。
3. 直接执行沉淀脚本出现异常时，**自动触发 Agent CLI 自愈**；沉淀时就要为异常情况准备好**提示词模板**。
4. **最高安全规则：所有浏览器操作只能通过紫鸟 ZClaw bridge 在紫鸟店铺浏览器内执行，绝对禁止使用本机浏览器。**

## 二、评审发现的问题

### P0 — 与核心目标直接冲突

| # | 问题 | 位置 | 影响 |
|---|------|------|------|
| 1 | **参数化完全缺失**：引擎不读取 flow 的 `params`，CLI 无法传参，`${params.x}` 不解析 | `flow_engine.py` | "传参即可执行"的核心目标不成立；多店铺场景失效 |
| 2 | **branch 分支是假实现**：遇到 `on_fail.branch` 仅记录后继续顺序执行，不真正跳转 | 旧 `flow_engine.py` `_execute_steps` | "多分支选择"目标不成立；switch_language 在无需切换时仍执行了切换步骤（运行日志可证） |
| 3 | **失败步骤定位错误**：用 `context` 的最后一个 save 键名当失败步骤 ID | 旧 `flow_engine.py` `_trigger_self_heal` | 自愈 Agent 拿到错误的失败位置，诊断方向南辕北辙 |
| 4 | **自愈只绑定 OpenClaw**：`openclaw agent ...` 命令硬编码 | 旧 `self_heal.py` | 无法切换 Claude Code 等其他 Agent CLI |

## 三、优化方案（已实施）

### 1. 参数化（解决 #1）
- flow JSON 的 `params` 作为默认值，`_` 开头的键视为注释。
- CLI 传参：`python3 manager.py run <flow> -p store_name=前行信息 -p target_lang=en-US`。
- 步骤中以 `${params.key}` 引用；`@extracts/*.js` 文件内容同样做变量替换。
- 店铺选择优先级：`args.storeId/storeName` > `params.store_id/store_name` > `store_selector: first`。
- `retry` 沿用上次运行的参数（参数已写入 runs.jsonl）。

### 2. 真实分支（解决 #2）
- 新增 `branch` 动作：`cases[].condition` 命中则 `goto` 对应步骤，否则走 `default`。
- 任意步骤支持成功后 `goto` / `branch`；`on_fail.branch` 真正跳转；目标 `"end"` 表示正常结束。
- 引擎按步骤 id 索引跳转，并有执行次数上限防分支死循环。
- `switch_language` v2 已用真分支重写并真机验证（已是目标语言 → 跳过切换直达收尾）。

### 3. 结果校验（解决 #5）
- 步骤级 `validate`：`not_empty` / `min_rows` / `require_fields` / `contains`，支持 `path` 取子字段。
- 校验失败按失败处理（可触发自愈），杜绝"提取到空数据也算成功"。

### 4. 自愈链路修复与增强（解决 #3 #4 #6~#11）
- 精确记录失败现场：步骤 id、工具、已解析的入参、错误，失败时自动截图。
- Agent CLI 可配置：`config.json` 的 `heal.agents` 支持 openclaw / claude / cursor-agent，命令模板带 `{prompt}` 等占位符。
- 提示词模板外置到 `heal_templates/`，查找顺序：`<flow_id>/<error_type>.md` → `<flow_id>/generic.md` → `<error_type>.md` → 内置默认。
- flow JSON 新增 `heal.hints`：沉淀时写入该流程的页面入口、关键选择器、已知坑，自动并入提示词。
- 冷却与频控：同流程同步骤 60 分钟冷却、单流程每日上限 5 次（可配）。
- known_issues 命中已解决问题 → 不再触发 Agent（0 tokens 路径）。
- heal_id 全链路唯一；触发事件统一写 `learnings/heals.jsonl`。

### 5. 沉淀工程化（解决 #12~#14）
- 提取 JS 全部外置到 `extracts/*.js`（IIFE 包裹），流程中 `@extracts/xxx.js` 引用。
- 流程模板 `flows/_template.json` + 脚手架 `manager.py new <id> [名称]`。
- 静态校验 `manager.py validate <id>`：步骤 id 唯一性、跳转目标存在性、工具名合法性（对照 bridge 注册表）、`@extracts` 文件存在性、`${params.*}` 引用声明检查。
- 文档体系：`docs/`（本目录）+ `README.md`（人）+ `AGENTS.md`（Agent）。

### 6. 最高安全规则固化
- `zclaw_client.py` 是项目唯一网络出口，`_request()` 加入路径白名单硬约束：仅允许 `/zclaw/*` 端点，违例直接抛错。
- 全项目无 webbrowser / Playwright / Selenium / Puppeteer / 本机浏览器调用（已用全局扫描验证）。
- 自愈提示词内置约定，要求 Agent 修复时同样只能走 ZClaw bridge。

## 五、后续建议（未实施，可选）

1. **自愈结果回采**：Agent 修复后自动验证的结果目前靠 Agent 自觉写 known_issues；可增加 `manager.py heal-verify <heal_id>` 做机器复核。
2. **多店铺批量执行**：`run-all` 目前按流程串行；可扩展 `-p store_name=*` 遍历店铺列表。
3. **产出物保留策略**：output/ 与 logs/ 无清理机制，长期运行需要按日期归档。
4. **飞书直连告警**：当前告警依赖 OpenClaw 的 `--deliver --channel feishu`；换用其他 Agent CLI 时需补独立的通知通道。
