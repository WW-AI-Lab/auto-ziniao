# 紫鸟自动化引擎 — 架构设计（v2）

## 最高安全规则（先于一切）

**所有浏览器操作只能通过紫鸟 ZClaw bridge（`http://127.0.0.1:9481/zclaw/*`）在紫鸟店铺浏览器内执行。绝对禁止使用本机浏览器（Chrome/Safari/Edge/Firefox）或 Playwright/Selenium/Puppeteer 等自动化框架。**

落地方式：
- `zclaw_client.py` 是项目**唯一**的网络出口，`_request()` 内置路径白名单（仅 `/zclaw/*`），违例抛 `ZClawError`。
- 打开页面只有两种合法方式（与 Skill 原始方法一致）：店铺已开用 `visit_page`；未开用 `open_store`（可带 `launchUrl`）。店铺浏览器由紫鸟客户端按其自身 `store/detail` + 启动逻辑拉起。
- 自愈提示词中内置同样的约定，约束自愈 Agent 的行为。

## 核心理念：三态闭环

```
┌─────────────────────────────────────────────────────────────┐
│ ① 沉淀（消耗 tokens，一次性）                                  │
│    Agent 用 ziniao-assistant skill 跑通任务                   │
│    → manager.py new 脚手架 → 写 flow JSON + extracts/*.js    │
│    → 写 heal.hints（给未来自愈 Agent 的线索）                  │
│    → validate 校验 → run -v 真机验证 → 固化                   │
├─────────────────────────────────────────────────────────────┤
│ ② 常态执行（0 tokens）                                        │
│    cron / manager.py run <flow> -p k=v                       │
│    → flow_engine.py 纯脚本执行（参数/分支/校验/重试）           │
│    → 成功：产出落盘 output/，日志 logs/runs.jsonl              │
├─────────────────────────────────────────────────────────────┤
│ ③ 自愈（消耗 tokens，仅异常且未命中已知问题时）                  │
│    失败 → 截图 + 组装失败现场 → 查 known_issues（命中即停，0t） │
│    → 冷却/频控检查 → 渲染提示词模板 → 调用 Agent CLI            │
│    → Agent 诊断修复 → 重跑验证 → 写回 known_issues（沉淀）      │
└─────────────────────────────────────────────────────────────┘
```

## 模块职责与数据流

```
manager.py / cron
   │  flow_id + params
   ▼
flow_engine.py ──────────────── 失败 ──────────────► self_heal.py
   │ 步骤循环：                                        │ classify_error
   │  条件跳过 → branch/goto 跳转                      │ check_known_issues（命中→停）
   │  工具步骤 → zclaw_client.invoke                  │ check_cooldown（冷却→停）
   │  动作步骤 → save_json/assert/...                 │ 模板渲染（flow hints 注入）
   │  validate 校验 → on_fail 策略                    │ subprocess → Agent CLI
   ▼                                                  ▼
zclaw_client.py                                  openclaw / claude / cursor-agent
   │ POST /zclaw/tools/invoke（白名单硬约束）           │ 诊断→修复→验证→写 known_issues
   ▼                                                  
紫鸟 ZClaw bridge (127.0.0.1:9481) → 紫鸟店铺浏览器
```

## 流程引擎关键设计

### 变量系统
| 写法 | 含义 |
|------|------|
| `${params.key}` | 流程参数（flow 默认值 ← CLI `-p key=value` 覆盖） |
| `${save键.字段.子字段}` | 之前步骤 `save` 的结果，支持点路径与数组下标 |
| `${date}` / `${datetime}` / `${timestamp}` | 内置时间变量 |
| `@extracts/xxx.js` | 外部 JS 文件引用（内容同样做变量替换） |

纯引用（整串就是 `${x}`）返回原始类型（dict/list/int）；内嵌引用做字符串替换；未命中的 `${...}` 保留原样（兼容 JS 语法）。

### 异常控制（on_fail 五种策略）
| action | 行为 | tokens |
|--------|------|--------|
| `retry` | 本步骤重试 N 次 | 0 |
| `skip` | 记录后继续 | 0 |
| `branch` | 跳到 `target` 步骤（或 `end`） | 0 |
| `abort` | 中止流程 → 流程级重试 → 最终失败触发自愈 | 仅最终失败 |
| `heal` | 同 abort，且用 `context` 显式指定错误类型模板 | 仅最终失败 |

### 多分支选择
- `branch` 动作步骤：`cases[].condition` 顺序求值，命中即 `goto`；都不中走 `default`。
- 任意步骤成功后可 `goto` / `branch`。
- 条件类型：eq/ne/contains/not_contains/starts_with/is_true/is_false/gt/lt/is_empty/not_empty。
- 跳转目标 `"end"` = 正常结束；引擎有执行次数上限（步骤数×10）防死循环。

### 结果校验（validate）
`{"path": "products", "not_empty": true, "min_rows": 1, "require_fields": ["asin"], "contains": "xx"}`
校验失败等同步骤失败，走 on_fail 策略——保证"提取到空数据"不会被当成成功。

## 自愈机制关键设计

详见 `docs/04-自愈机制与提示词模板.md`。要点：

1. **错误自动分类** → 7 类（nav_failed / extract_failed / element_not_found / timeout / auth_failed / bridge_down / generic），步骤可用 `on_fail.context` 显式指定。
2. **提示词四层组装**：通用前缀（任务+失败现场+安全约定）→ 错误类型模板（可外置定制）→ 流程级 `heal.hints`（沉淀时编写）→ 修复闭环指令（验证+写 known_issues）。
3. **0 tokens 优先**：known_issues 命中已解决问题 → 不触发 Agent。
4. **防自愈风暴**：同流程同步骤冷却 60 分钟；单流程每日上限 5 次（config.json 可调）。
5. **多 Agent CLI**：config.json `heal.agents` 配置命令模板，`heal.agent` 选择默认；支持 openclaw / claude / cursor-agent，占位符 `{prompt}` `{prompt_path}` `{session_key}` 等。

## 调度

```bash
python3 manager.py cron   # 按各 flow 的 schedule 字段生成 crontab 建议
```
cron 直接调 `flow_engine.py run <flow_id>`，不依赖任何 Agent 进程；失败时由引擎内部触发自愈。

另有 webadmin 自带的独立计划任务调度（见下节），与 crontab 并存互不接管；同一 flow 请勿同时接入两套调度。

## Web 管理界面（webadmin，可选子工程）

```
浏览器(本机) ──HTTP/SSE──► webadmin (FastAPI, 仅 127.0.0.1:9482)
                              │
        ┌─────────────────────┼──────────────────────┐
        ▼                     ▼                      ▼
   flows/*.json          调度器线程                chat 适配层
   logs/ output/       (SQLite: schedules)     ┌─ OpenClaw gateway (HTTP, 可用时)
   learnings/(只读)           │                 └─ agent CLI (subprocess, 回退)
                              ▼
                    subprocess: python3 flow_engine.py run <id> -p k=v
                              │（既有链路，不变）
                              ▼
                    zclaw_client.py → ZClaw bridge(9481) → 紫鸟店铺浏览器
```

要点：

- **隔离**：webadmin 是独立子工程（`webadmin/requirements.txt`：fastapi + uvicorn），引擎四件套不 import 它，删除 `webadmin/` 即完全回滚。
- **执行一致性**：flow 一律 subprocess 调 `flow_engine.py run`，与 cron/手工路径一致，失败自愈仍由引擎处理；flow 级进程内锁防重（手动与调度共用）。
- **数据**：webadmin 自有数据（计划任务、调度历史、chat 会话/消息）存 SQLite（`webadmin/data/webadmin.db`，WAL）；引擎 JSON/JSONL 只读消费，flows 编辑保存前强制引擎校验并自动备份（`flows/.backup/`，保留 5 份）。
- **安全**：仅回环监听、无登录；文件 API 白名单根目录 + 路径规范化校验；webadmin 不直接调用 ZClaw bridge。
- **chat**：agent 清单复用 `config.json` `heal.agents`；openclaw 优先 gateway `/v1/chat/completions`（SSE 流式），端点未启用/不可达时自动回退 CLI（去 `--deliver`/`--channel` 投递参数）。

## 技术栈

- Python 3.9+，零第三方依赖（urllib + 标准库）
- 数据存储：JSON / JSONL（无数据库）
- 调度：系统 crontab
- 自愈 Agent：可配置 CLI（OpenClaw / Claude Code / Cursor）
