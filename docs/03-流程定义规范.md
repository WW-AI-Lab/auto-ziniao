# 流程定义规范（flow JSON）

> 沉淀任务时必须遵循本规范。脚手架：`pnpm ziniao new <flow_id> [名称]`；校验：`pnpm ziniao validate <flow_id>`。

## 顶层字段

| 字段 | 必填 | 说明 |
|------|------|------|
| `id` | ✅ | 流程唯一 ID，与文件名一致（`flows/<id>.json`） |
| `name` | ✅ | 中文名称 |
| `version` | ✅ | 每次修改 +1（自愈修复后也要 +1） |
| `enabled` | ✅ | 禁用后 `run-all` 与 cron 建议会跳过 |
| `schedule` | - | cron 表达式，空串表示不定时 |
| `description` | ✅ | 一句话说明做什么、产出什么 |
| `retry` | - | 流程级重试 `{maxAttempts, delayMs}`（整个流程从头重跑） |
| `params` | - | 参数默认值；`_` 开头的键是注释。执行时 `-p k=v` 覆盖 |
| `steps` | ✅ | 步骤数组（见下） |
| `on_success` | - | `{close_store: bool}` 成功后是否关店 |
| `on_fail_final` | - | `{notify, close_store, heal}`；`heal: false` 禁用该流程自愈 |
| `heal` | 强烈建议 | `{hints: "..."}` 给自愈 Agent 的流程特定线索（见 04 文档） |

## 内置参数约定

| 参数 | 约定 |
|------|------|
| `store_name` | 店铺名（精确匹配）。为空时用店铺列表第一个。所有流程都应声明它 |
| `store_id` | 店铺 ID，优先级高于 store_name |

店铺选择优先级：步骤 `args.storeId/storeName` > `params.store_id` > `params.store_name` > `store_selector: "first"`。

## 步骤结构

每个步骤必须有唯一 `id`，且有 `tool`（ZClaw 工具）或 `action`（引擎内置动作）二选一。

```json
{
  "id": "extract_data",
  "tool": "execute_script",
  "args": { "script": "@extracts/xxx.js", "returnByValue": true },
  "save": "result_data",
  "condition": { "type": "eq", "left": "${flag}", "right": "yes" },
  "validate": { "not_empty": true, "require_fields": ["url"] },
  "on_fail": { "action": "heal", "context": "extract_failed" },
  "goto": "next_step_id",
  "branch": { "cases": [ { "condition": {...}, "goto": "a" } ], "default": "b" }
}
```

| 字段 | 说明 |
|------|------|
| `save` | 结果存入上下文，后续用 `${save键.字段}` 引用 |
| `condition` | 条件不满足则跳过本步骤（顺序继续） |
| `validate` | 结果校验，失败按 on_fail 处理 |
| `on_fail` | 失败策略（见下） |
| `goto` / `branch` | 成功后跳转（`"end"` = 正常结束） |

### 合法工具名（tool）

以 `GET http://127.0.0.1:9481/zclaw/tools` 返回为准，**禁止臆造**。当前 20 个：
`list_stores` `resolve_store` `open_store` `close_store` `visit_page` `get_page_content` `query_elements` `click_element` `input_text` `scroll_page` `take_screenshot` `wait_for_element` `wait_for_navigation` `execute_script` `run_automation` `extract_data` `prepare_agent` `download_file` `get_logs` `debug_compare_lists`

`storeId` / `targetId` 由引擎自动注入，args 中通常不必写。

### 内置动作（action）

| action | 参数 | 说明 |
|--------|------|------|
| `sleep` | `seconds` | 等待 |
| `save_json` / `save_csv` | `data` `filename`（`header` 仅 csv） | 落盘到 data/output/，文件名支持 `${date}` |
| `print` | `message` | 打印（支持变量） |
| `assert` | `value` `expected` `check`(eq/ne/gt/contains/not_empty) | 断言失败 = 步骤失败 |
| `fail` | `message` | 主动失败（配合分支标记异常页面状态） |
| `branch` | `cases[]` `default` | 多分支跳转 |
| `goto` | `target` | 无条件跳转 |
| `close_store` | - | 关闭当前店铺 |

### on_fail 策略

| action | 附加字段 | 行为 |
|--------|----------|------|
| `abort`（默认） | `context`（可选，错误类型提示） | 中止 → 流程级重试 → 最终失败触发自愈 |
| `retry` | `delayMs` `maxAttempts` | 本步骤重试 |
| `skip` | - | 记录后继续 |
| `branch` | `target` | 跳到指定步骤 |
| `heal` | `context`（错误类型：见 04 文档） | 同 abort，并显式指定自愈模板 |

### 条件表达式

`{"type": "<类型>", "left": "${变量}", "right": "值或${变量}"}`
类型：`eq` `ne` `contains` `not_contains` `starts_with` `is_true` `is_false` `gt` `lt` `is_empty` `not_empty`

## 提取脚本规范（extracts/）

1. **必须**外置为 `extracts/<名称>.js`，流程中 `"script": "@extracts/<名称>.js"` 引用；禁止在 flow JSON 里内联长脚本。
2. **必须** IIFE 包裹：`(function(){ ... })()`。
3. 返回结构化数据用 `return JSON.stringify(obj)`（客户端会自动反序列化）。
4. 可使用 `${params.x}` 占位符（引擎执行前替换）；**禁止**使用 JS 模板字符串 `` `${}` ``，避免与引擎变量冲突。
5. 页面可能是中英文，文本匹配要兼容两种语言。
6. 提取结果应包含 `url` 和时间戳字段，便于排查。

## 沉淀检查清单（Checklist）

- [ ] `pnpm ziniao new <flow_id>` 创建，按真机跑通的步骤填写
- [ ] 声明 `params`（至少 `store_name`），不硬编码店铺/日期
- [ ] 提取 JS 外置到 `extracts/`，IIFE 包裹
- [ ] 关键步骤配 `validate`（拒绝空数据假成功）
- [ ] 每个可能失败的步骤配 `on_fail`（瞬时问题 retry，结构问题 heal）
- [ ] 有状态判断的场景用 `branch` 写多分支（如：已登录/未登录、有数据/无数据）
- [ ] 填写 `heal.hints`：页面入口、关键选择器、页面结构特征、已知坑
- [ ] `pnpm ziniao validate <flow_id>` 通过
- [ ] `pnpm ziniao run <flow_id> -v --no-heal` 真机跑通
- [ ] 确认 data/output/ 产出正确后再启用 schedule
