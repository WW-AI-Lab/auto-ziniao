# TypeScript 迁移进度与路线图

> 状态日期：2026-06-15  
> 目标：用一个专门文件跟踪 TS 迁移当前状态、已完成边界、下一步 OpenSpec change 和剩余工作。长期架构设计仍以 `docs/05-TS重构技术蓝图.md` 为准。

## 当前结论

当前迁移已完成 **M1：契约与 TS 骨架**、**M2：安全出口可用**、**M3：Flow Engine 迁移**、**M4：Self-Heal 迁移**、**M5：CLI 迁移** 和 **M6：WebAdmin 后端 TS 化**。生产入口仍是 `python3 manager.py ...`；TypeScript 目前已经具备 flow 加载、静态校验、离线执行语义、mock ZClaw tool dispatch、output/run log 兼容写入、本地双跑验证能力，self-heal 的错误分类、known issues、prompt/context 生成、cooldown、Agent CLI adapter、dry-run，`ziniao ...` 过渡 CLI 能力，以及 `apps/webadmin-api` 的 Fastify WebAdmin API 能力。

**M6：WebAdmin 后端 TS 化** 已由 OpenSpec change `add-typescript-webadmin-api` 实现。仓库已新增 `apps/webadmin-api`，覆盖 flows 管理、运行观测、计划任务调度、Agent chat SSE、静态前端 dist 托管、SQLite WebAdmin 自有状态、离线测试和安全扫描。M6 完成后仍不得把生产入口从 `python3 manager.py ...` 切到 TS；现有 Python WebAdmin 后端也仍保留，切换必须等后续双跑验证和入口切换 change。

当前主规格：

- `typescript-zclaw-client`
- `typescript-flow-engine`
- `typescript-self-heal`
- `typescript-cli`

- `add-typescript-flow-pacing-policy`：TS flow-engine 操作节奏策略提案；不迁移 CLI，不改变 Python 生产入口。

- 安全扫描新增 `packages/self-heal` 禁止依赖/import `@ziniao/zclaw` 的规则

### M5：CLI 迁移

已由 OpenSpec change `add-typescript-cli` 落地：

- `packages/cli`
- workspace package `@ziniao/cli`
- bin 入口 `ziniao`
- CLI 框架 `commander`
- 命令：`list`、`run`、`run-all`、`retry`、`new`、`validate`、`history`、`enable`、`disable`、`heals`、`stats`、`cron`
- `--repo-root` / `--data-root` 测试注入入口
- `run` 支持 `-p/--param`、`-v/--verbose`、`--no-heal`、`--heal-dry-run`
- 通过 `packages/flow-engine` 执行 flow，不直接访问 bridge

- CLI 离线 Vitest 覆盖 flow 管理、运行、自愈 mock/dry-run、history/heals/stats/cron
- 安全扫描扩展：`packages/cli` 禁止 direct bridge 访问、ZClaw API key 读取、`@ziniao/zclaw` 直接依赖、浏览器自动化依赖

验收状态：

- `pnpm security:scan`

### M6：WebAdmin 后端 TS 化

已由 OpenSpec change `add-typescript-webadmin-api` 落地：

- `apps/webadmin-api`
- workspace package `@ziniao/webadmin-api`
- Fastify app factory 与启动入口，默认仅监听 `127.0.0.1`
- REST API：flows 列表/详情/validate/save/manual run/status
- monitoring API：runs、heals、known issues、stats、output 浏览/预览/下载
- schedules API：CRUD、enable/disable、`interval` / `daily` / 五字段 `cron`、调度历史
- in-process scheduler、flow-level lock、missed trigger 不补跑
- chat API：agents、sessions、messages、SSE send，默认测试使用 mock `AgentRunner`
- 静态托管当前 `webadmin/frontend/dist`，缺失 dist 时 API 仍可用
- `packages/schemas` 补齐 WebAdmin API DTO 与 `webadmin-api.schema.json`
- 安全扫描扩展到 `apps/*`，阻断 direct bridge、ZClaw API key、本机浏览器和浏览器自动化依赖

SQLite 选型记录：

- design 优先评估 `better-sqlite3`。
- 当前 pnpm 安装策略忽略 native build script，导致 `better-sqlite3` binding 不可用。
- M6 按 design 允许的替代方案改用 Node 24 内置 `node:sqlite`，保持同步 SQLite 访问模型；运行测试会出现 Node 的 experimental warning，但 baseline 通过。

验收状态：

- `pnpm --filter @ziniao/webadmin-api typecheck`
- `pnpm --filter @ziniao/webadmin-api test`
- `pnpm typecheck`
- `pnpm test`
- `pnpm build`
- `pnpm schemas:export -- --check`
- `pnpm security:scan`
- `pnpm validate:baseline`
- 精确边界检查：`rg -n "9481|/zclaw/tools|ZCLAW_API_KEY|\\.zclaw" apps/webadmin-api/src` 无命中
- `python3 manager.py list`
- `python3 manager.py validate orders_overview`

M6 边界：

- `apps/webadmin-api` 是 TS WebAdmin 后端能力，不替换当前 Python WebAdmin 生产链路。
- `webadmin/frontend/` 未移动，`apps/webadmin-frontend` 未创建。
- WebAdmin API 不直接访问 ZClaw bridge，不读取 ZClaw API key，不打开本机浏览器。
- 默认 baseline 只使用离线 mock、临时 data root、固定 clock 和 no-op sleeper，不执行真实 flow，不调用真实 Agent CLI。

## 当前边界

当前仍未改变生产路径：

- `manager.py` 仍转发到 Python `engine/manager.py`
- 真实 flow 执行仍由 Python `engine/flow_engine.py` 完成
- 自愈仍由 Python `engine/self_heal.py` 完成
- WebAdmin 后端仍是当前 FastAPI 子工程
- TS `apps/webadmin-api` 已可作为后续 WebAdmin 双跑基础，但当前 WebAdmin 生产链路仍未切换

当前禁止事项：

- 不得把生产入口切到 TS。
- 不得在未经双跑验证前把 WebAdmin 生产入口切到 `apps/webadmin-api`。
- 不得在 baseline 验证中执行真实 flow。
- 不得在 baseline 验证中调用真实 `POST /zclaw/tools/invoke`。
- 不得在 baseline 验证中调用真实 OpenClaw/Claude/Cursor Agent CLI。
- 不得绕过 `packages/zclaw` 直接访问 ZClaw bridge。
- 不得引入 Playwright/Selenium/Puppeteer/browser-use。

## 回滚原则

- M1/M2 均不改变 Python 生产执行链路。
- M3 在完成双跑切换前也不得替换生产入口。
- M4 也不得替换生产入口；回滚可删除或隔离 `packages/self-heal`，恢复 root script/path alias/security scan 改动。
- M5 在完成双跑切换前也不得替换生产入口；回滚可删除或隔离 `packages/cli`，恢复 root workspace 配置、安全扫描和文档中的 M5 改动。
- M6 在完成 WebAdmin 双跑切换前不得替换 Python WebAdmin 生产入口；回滚可删除或隔离 `apps/webadmin-api`，恢复 root workspace 配置、安全扫描和文档中的 M6 改动。
- 任一阶段回滚时，优先删除或隔离对应新增 TS 包，并恢复 root scripts、alias 与安全扫描规则。
- 回滚后必须验证：

```bash
python3 manager.py list
python3 manager.py validate orders_overview
```
