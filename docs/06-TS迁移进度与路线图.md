# TypeScript 迁移进度与路线图

> 状态日期：2026-06-14  
> 目标：用一个专门文件跟踪 TS 迁移当前状态、已完成边界、下一步 OpenSpec change 和剩余工作。长期架构设计仍以 `docs/05-TS重构技术蓝图.md` 为准。

## 当前结论

当前迁移已完成 **M1：契约与 TS 骨架**、**M2：安全出口可用** 和 **M3：Flow Engine 迁移**。生产入口仍是 `python3 manager.py ...`；TypeScript 目前已经具备 flow 加载、静态校验、离线执行语义、mock ZClaw tool dispatch、output/run log 兼容写入和本地双跑验证能力，但还没有迁移 self-heal、CLI 或 WebAdmin。

当前主规格：

- `flow-contract-schemas`
- `flow-compatibility-baseline`
- `typescript-workspace-baseline`
- `typescript-zclaw-client`
- `typescript-flow-engine`

当前 TS 包：

- `packages/core`
- `packages/schemas`
- `packages/zclaw`
- `packages/flow-engine`

验收状态：

### M3：Flow Engine 迁移

已由 OpenSpec change `add-typescript-flow-engine` 落地：

- `packages/flow-engine`
- `loadFlow(flowId | filePath)`
- `validateFlow()` wrapper，复用 `packages/schemas.validateFlowContract()`
- `parseParams(pairs)`
- `FlowRunner` / `runFlow()`
- 参数合并、`${params.x}`、`${step_save.path}`、`${date}`、`${datetime}`、`${timestamp}`

- `data/logs/runs.jsonl` schema-compatible append
- 当前五个 flow 的离线语义/golden 测试

## 当前边界

当前仍未改变生产路径：

- `manager.py` 仍转发到 Python `engine/manager.py`
- 真实 flow 执行仍由 Python `engine/flow_engine.py` 完成
- 自愈仍由 Python `engine/self_heal.py` 完成
- WebAdmin 后端仍是当前 FastAPI 子工程
- TS `packages/flow-engine` 仅作为后续 CLI/WebAdmin 切换前的执行核心能力与双跑验证基础

当前禁止事项：

- 不得把生产入口切到 TS。
- 不得在 baseline 验证中执行真实 flow。
- 不得在 baseline 验证中调用真实 `POST /zclaw/tools/invoke`。
- 不得绕过 `packages/zclaw` 直接访问 ZClaw bridge。
- 不得引入 Playwright/Selenium/Puppeteer/browser-use。

## 回滚原则

- M1/M2 均不改变 Python 生产执行链路。
- M3 在完成双跑切换前也不得替换生产入口。
- 任一阶段回滚时，优先删除或隔离对应新增 TS 包，并恢复 root scripts、alias 与安全扫描规则。
- 回滚后必须验证：

```bash
python3 manager.py list
python3 manager.py validate orders_overview
```
